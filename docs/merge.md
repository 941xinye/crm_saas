# 重复数据合并工具

公司 / 联系人存在重复录入时，在详情页一键合并：把重复项（源）的全部关联数据迁移到主记录（目标），空缺字段回填后源转入回收站（软删除，可恢复）。

## 入口

- **公司详情页** → 底部「合并重复公司」卡片：自动列出**同名**其他公司作为合并候选；
- **联系人详情页** → 底部「合并重复联系人」卡片：自动列出**同名**（姓 + 名）其他联系人作为合并候选。

> 联系人邮箱已有 `(tenant_id, email)` 唯一约束，同邮箱记录无法共存，因此联系人重复维度是姓名；公司重复维度是名称。

## 合并行为

| 数据 | 公司合并 | 联系人合并 |
|------|---------|-----------|
| 关联记录迁移 | 联系人、商机、活动、附件 → 目标公司 | 商机、活动、附件 → 目标联系人 |
| 空字段回填 | 行业 / 网站 / 电话 / 地址（目标已有值不覆盖） | 公司 / 职位 / 电话（目标已有值不覆盖） |
| 自定义字段 | 目标缺失或为空的键取源值，已有值不动 | 同左 |
| 源记录 | 软删除（回收站可恢复） | 软删除 |

## 安全与审计

- **租户隔离**：源与目标必须同租户，否则拒绝（显式校验 `tenant_id`，防跨租户注入）；
- **数据权限**：需要「更新目标 + 删除源」权限——公司/联系人的删除权限为 `admin` 专属，即合并仅租户管理员可执行（manager 可编辑但不可删除 → 不可合并）；
- **事务**：子记录迁移、回填、软删除在单个数据库事务内执行，任一步失败整体回滚；
- **审计**：通过 `AuditService::withBatch('merged', ...)` 聚合，源记录的 `deleted` 审计与 `batch_merged` 汇总日志共享同一 `batch_id`，审计日志页可按 batch_id 追溯完整操作。

## 实现

- 服务层：[app/Services/MergeService.php](../app/Services/MergeService.php)（`mergeCompanies` / `mergeContacts`）；
- 组件：[app/Livewire/Companies/Merge.php](../app/Livewire/Companies/Merge.php) 与 [app/Livewire/Contacts/Merge.php](../app/Livewire/Contacts/Merge.php)，嵌入对应详情页；
- 子记录迁移使用 `withoutTenant()` + 显式 `tenant_id` 条件（操作对象已校验归属，迁移语句不依赖请求上下文）。

## 测试

`tests/Feature/MergeTest.php`（9 项）覆盖：

- 公司合并：联系人/商机/活动/附件全部迁移、空字段回填且已有值不被覆盖、源软删除
- 联系人合并：商机/活动迁移、电话与职位回填
- 审计：源 deleted 审计与 batch_merged 汇总共享 batch_id、tenant_id 取自被操作对象
- 跨租户合并拒绝（公司 + 联系人）
- sales 无权合并（Policy）
- 详情页组件：同名候选展示、Livewire 选择→合并全流程、未选择时报错
